# USDC native reference-reading feasibility

**Exploratory research; non-authoritative; coverage PARTIAL.** This extends the [earlier options comparison](2026-10-22-usdc-reference-coverage-v0-2.md). It selects no architecture and creates no approved design, specification, implementation plan, or implementation.

**Recommendation: GO for bounded feasibility experiments; NO-GO for shipping complete arbitrary-USDC reference coverage on current evidence.** Prioritize an independently bounded native reader over a runtime resolver dependency. Start by testing an exact crate `0.8.0` tranche, retain explicit partial coverage for everything unproved, and resolve the compression discrepancy below before treating the decoding recipe as settled. This is a conditional research recommendation, not authorization to implement.

## What the native boundary can retain—and must change

Verified: native inspection uses a stable read-only file, an exact in-memory package namespace and fixed ceilings; it promises no extraction, decompression, stage loading or host-filesystem reference resolution. Every recognized USDA layer is scanned, including unreferenced layers and inactive authoring. [inspection-boundary.md:3–25](../../../docs/inspection-boundary.md#L3-L25)

Verified: crate structural data includes LZ4-compressed tokens, compressed field/value tables and compressed field-set indices. The pinned reader actually calls `TfFastCompression` for token data and field value representations. Stored ZIP members therefore do not remove the need for **internal crate-block decompression**. [N:10608–10698](https://github.com/aousd/specifications-public/blob/2f9e746c4fbd7f48d6d2c9ac568133fe398bbfc0/core/1.0.1/core_spec.md#L10608-L10698), [U crateFile.cpp:3660–3677](https://github.com/PixarAnimationStudios/OpenUSD/blob/96c1989167d2aaab5bd34627f32a321a6b79866b/pxr/usd/sdf/crateFile.cpp#L3660-L3677), [U:3830–3838](https://github.com/PixarAnimationStudios/OpenUSD/blob/96c1989167d2aaab5bd34627f32a321a6b79866b/pxr/usd/sdf/crateFile.cpp#L3830-L3838)

Inference: a bounded decoder could retain read-only, package-local lookup without extracting members or resolving host paths, but it would extend the existing broad **no-decompression** promise. That product-boundary change needs a later explicit decision. If literally no decompression must remain, this native tranche is **NO-GO**.

The desired inventory is authored asset values in **every eligible recognized layer**, not merely references reachable from the root or active composed dependencies. Preserve the original ZIP author directory for relative lookup; neither a composed stage nor token/string scanning certifies that inventory. The current resolver already provides package-only target policy, while binary identification currently records `UVK-LIM-002` before any enumeration. [ReferenceResolver.swift:3–75](../../../Sources/USDZValidation/Rules/ReferenceResolver.swift#L3-L75), [NativeEngine.swift:156–206](../../../Sources/USDZValidation/NativeEngine.swift#L156-L206), [USDLayer.swift:65–87](../../../Sources/USDZValidation/Rules/USDLayer.swift#L65-L87)

## Minimum candidate subset: a research tranche, not conformance

**Proposed initial gate: exact crate `0.8.0`.** AOUSD 1.0.1 describes a `0.8.0–0.12.0` band and requires readers implementing that specification to support its latest version. Upstream still defaults new files to `0.8.0`, but its implementation version is `0.16.0`, with later features including ArrayEdits. Thus this narrow tranche is neither AOUSD conformance nor general modern-USDC support; it is a testable starting hypothesis. Older/newer/unknown versions remain explicitly partial until individually justified. ## Experiments that determine go/no-go

These are unresolved research questions, not an implementation plan; none were performed here.

1. **Reconcile actual encoding.** Which single/chunked structural block bytes do version-pinned writers produce, and how do pinned readers consume them? Resolve the N/U/S width discrepancy with original minimal fixtures, byte-level expected tables and authoritative clarification. Failure to reconcile is a shipping no-go.
2. **Prove authored-value coverage.** Can the exact-`0.8.0` candidate reproduce independently authored occurrences across all eligible layers, scalar/array values, sublayers, all list-op buckets, dictionaries/wrappers, customData, time samples and inactive authoring? Include no-reference and duplicate cases; verify live-table joins and absence of interned-string false positives. Record real corpus versions; existing Apple samples are not a version census.
3. **Prove bounded decoding before allocation.** Test forged counts/indices/offsets, decoded expansion, truncated input, cycles, deep dictionaries/path structures and aggregate work. The official array-size advisory demonstrates delayed unpacking can request attacker-controlled allocation, with checks added in 26.08 under the safety option; `max_size()` is not this project's 256 MiB budget. The path-index advisory likewise motivates explicit bounds. Neither advisory establishes Apple's vulnerability status. [A:array-size](https://github.com/PixarAnimationStudios/OpenUSD/security/advisories/GHSA-8878-wr6v-j5cm), [A:path-index](https://github.com/PixarAnimationStudios/OpenUSD/security/advisories/GHSA-2mw3-69cm-cv25)
4. **Prove package-only behavior and reporting.** Trace prohibited host/network/tool access attempts, preserve author directories and input-byte identity, and verify partial/unsupported versus established malformed outcomes. Test original locators, duplicate identities, redaction, JSON/SARIF and exits. Current gaps are persistent, and policy findings themselves can mark references partial; successful enumeration cannot simply erase `UVK-LIM-002` afterward. [NativeDiagnostics.swift:136–163](../../../Sources/USDZValidation/NativeDiagnostics.swift#L136-L163), [ReferenceResolver.swift:143–159](../../../Sources/USDZValidation/Rules/ReferenceResolver.swift#L143-L159)
5. **Measure and close release obligations.** Validate actual compression/runtime dependency and notice inventory, current-host and intended deployment builds, decoded-memory/work ceilings, RSS/time and repeatability. Widen to `0.9–0.12` only with version-specific evidence; do not call that support for `0.13–0.16` or arbitrary future crates.

**Decision threshold.** Native package-local reading is a plausible research direction because the format separates structural metadata and on-demand typed values; no full scene evaluation is inherently required for this proposed authored subset. That remains an inference, supported by [N:10357–10362](https://github.com/aousd/specifications-public/blob/2f9e746c4fbd7f48d6d2c9ac568133fe398bbfc0/core/1.0.1/core_spec.md#L10357-L10362), not a working parser proof. Proceed only with feasibility evidence gathering. Shipping a “complete USDC” claim, replacing the native gap with convenience-API success, or promising the unchanged v0.1 boundary is no-go now.
